# Reel Lens — mobile

Expo (SDK 57) app for iOS and Android. Share a reel from Instagram into it, watch
the analysis progress, then read the reel's details and ask questions about it.

## Run it

Needs Xcode (iOS) and/or Android Studio (Android) — the share sheet is native code,
so this runs as a development build, **not in Expo Go**.

```bash
npm install
npm run env        # writes .env.local from the ReelLensMultiTenant stack outputs
npm run android    # or: npm run ios
```

`npm run env` must run before bundling: `EXPO_PUBLIC_*` values are inlined at build
time, like `NEXT_PUBLIC_*` on the web. `ios/` and `android/` are generated by
`expo prebuild` from `app.json` and are gitignored — never edit them by hand.

## Testing the share sheet

- **Android emulator** (a system image *with Google Play*): install Instagram from
  Play, open a reel, Share → Reel Lens. This is the real end-to-end path.
- **iOS Simulator**: Instagram cannot be installed there. Share an instagram.com
  reel link from Safari instead — same extension, same code path.
- **iPhone**: needs an Apple Developer team set on both the app and the
  `SavetoReelLens` extension target (they share the `group.com.reellens.app` App Group).

## How it fits the backend

- **Sign-in** is the Cognito Hosted UI with code + PKCE through the *same* app client
  as the web, redirecting to `reellens://auth/callback`. The API's authorizer accepts
  the tokens unchanged. Tokens are kept in SecureStore.
- **Sharing** posts the permalink to `POST /media/url`. A reel anyone has already
  analysed is returned immediately, with no second download.
- **Progress** comes over the same WebSocket as the web, with a 10s poll as a fallback.
- **Ask** is `POST /ask` scoped to the reel; citations seek the player (or turn to the
  slide, for a carousel).
- **The Ask tab** asks across the whole library. A question gets one cited answer; a
  request ("create me a travel plan for Istanbul with all the tips") builds a plan in the
  background (`mode: 'plan'`, about a minute) and the thread screen polls for it. The mode
  is a local guess shown as a chip, one tap to override.
- **Pictures** beside each tip are the keyframe the tip was read from, looked up through
  `GET /media/{id}` (one call per cited reel) — no backend change.
- **Share PDF** renders the plan on the phone (`expo-print`) with the plan's title and
  "Curated by Reel Lens app" at the top, and hands it to the share sheet, where the user
  picks the app and the recipient. Pictures are inlined as base64 because iOS will not
  load image URLs while printing HTML.

## Gotcha

`iosShareExtensionName` must not reduce to the app's own target name: the plugin
strips non-alphanumerics, so "Reel Lens" became `ReelLens`, collided with the app
target, and the extension was silently never created. It is "Save to Reel Lens",
which is also what the share sheet shows.
